# WL-P1-006: Make the full test suite pass cleanly in sandboxed agent environments

## Goal

The sandboxed Python suite reported an error when the native Web restart test tried to reserve a loopback TCP port. Report a skip when the sandbox denies that permission and preserve failures that indicate a test or application problem.

## Acceptance criteria

- [x] The EPERM test is identified and either skips with a precise reason when the capability is missing, or the sandbox need is documented.
- [x] No real failure is hidden: the test still runs and must pass when the capability exists.
- [x] docs/development.md lists which suites need Docker, local port binding or network.

## Plan

- [x] Run the full suite in a sandbox and capture the failing test id.
- [x] Decide skip versus documentation with the reviewer.
- [x] Implement and document.

## Handoff

- State: The current base reproduces `EPERM` in `test_web.WebTests.test_native_server_restart_preserves_session_and_settings`. The fix skips that test only for `EACCES` or `EPERM` at port reservation. The earlier full sandbox run went from one error in 1,227 tests to zero errors with one additional skip. On the current base with the fix, the focused test skips in the sandbox and passes with loopback access.
- Next step: Review the current-base full suite and candidate image evidence before requesting approval to publish.
- Verify: `PYTHONPATH=src python -m unittest discover -s tests -v` with the locked Web test dependencies. Run `PYTHONPATH=src:tests python -m unittest -v test_web.WebTests.test_native_server_restart_preserves_session_and_settings` with loopback access to verify the restart assertions.
- Gotchas: Keep the exception handler around port reservation. Startup, readiness and persistence failures must still fail the test.
- Open questions: None.
