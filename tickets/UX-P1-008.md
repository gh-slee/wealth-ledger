# UX-P1-008: Lead the Overview with the portfolio value and collapse evidence detail

## Goal

A returning user opens the Overview to see what the portfolio is worth. The value is shown, but an expanded evidence panel with next-step cards follows it and pushes the chart and the account breakdown several screens down. WL-P0-011 already bans these home-page concepts from the V2 Home; this ticket brings the same relief to the shipped application. Every evidence item stays reachable behind one collapsed control.

## Context

### Current behaviour

- Observed on the synthetic browser fixture on 2026-11-10: at 1024x768 the value is visible, then "Evidence for this saved edition" shows three dated facts, "Next steps (4)" with three expanded cards and "Saved evidence and checks" before the first chart. At 375x812 the value starts 989 px down the page.
- `frontend/src/App.tsx:553` renders `<Evidence>` (the date rail) above every analysis page, then `<Overview>`.
- `frontend/src/components/analysis.tsx:60` `Overview` renders the value (`:78`), then `EvidenceStatus` (`frontend/src/components/evidence-status.tsx:100`) expanded, then the chart (`:112`) and account breakdown (`:147`).
- Items come from `evidenceItems` in `frontend/src/lib/evidence-status.ts:36`.

### Expected behaviour

- The Overview shows, in this order: value with its valuation cutoff and scope badge, account breakdown, value chart, then one summary line such as "2 to review, 2 unknown" that expands the existing evidence panel.
- A partial or unknown total is still marked beside the value without expanding anything.
- Loading and error states are unchanged.

### Scope

- In scope: order and default disclosure state on the Overview; the summary line; locale keys.
- Out of scope: removing evidence data, changing `evidenceItems`, the date rail on other pages, any API or payload change, the V2 Home (WL-P0-012D).
- Non-goals: a new visual system; hiding unknown or partial status.

### Implementation notes

- Reuse the `<details>` pattern already used for "Saved evidence and checks".
- `frontend/tests/browser/evidence-status.spec.ts` asserts the expanded panel. Make the tests expand it first; keep their assertions.
- Read [DESIGN.md](../DESIGN.md) and [web-frontend.md](../docs/web-frontend.md) first. Add locale keys to all three catalogs in `frontend/src/locales/` in one block named for this ticket.
- Refresh the affected README screenshots with the synthetic fixture ([guide](../assets/readme/README.md#when-to-refresh-screenshots)).

## Acceptance criteria

- [ ] Given a published report, when the Overview loads at 1024x768, then the value, its valuation cutoff, the scope badge and the top of the account breakdown are visible without scrolling.
- [ ] Given the same report at 375x812, then the value is within the first 812 px of the document (after UX-P1-015) or no lower than today (before it).
- [ ] Given evidence items with status review or unknown, when the Overview loads, then one summary line states their counts and the panel is collapsed; activating the line by mouse, Enter or Space expands the same items and actions that exist today.
- [ ] Given a report with partial source scope, then the partial badge and its one-sentence explanation are visible beside the value without expanding anything.
- [ ] Given no evidence items, then no summary line is shown.
- [ ] en-CA, zh-TW and zh-CN, light and dark themes pass the browser checks.
