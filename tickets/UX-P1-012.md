# UX-P1-012: Show every label in the selected language and keep internal codes out of the page

## Goal

With the interface in English the Holdings table shows a Traditional Chinese account label and security name, the Overview evidence panel prints a raw check code, and the sign-in page keeps English decoration in both Chinese locales. A reader in any locale should see every application-owned label in that language and never an internal identifier as the only explanation.

## Context

### Current behaviour

- Observed on the synthetic browser fixture on 2026-11-10: in en-CA the last Holdings row shows the Bull cash account and its name in Traditional Chinese, while the Overview shows the same account as "Self-custodied Bitcoin (Bull purchase records)".
- `src/wealth_ledger/combined.py:59-62` and `:246-260` write those labels into the saved payload. They are compatibility strings and must not change.
- `src/wealth_ledger/web/reports.py:259-261` passes account labels through `legacy_text` for the account list only. Holdings rows (`account_label`, cash `name`) reach the browser untranslated and `frontend/src/components/analysis.tsx:207` renders them as is.
- Observed on the synthetic browser fixture on 2026-11-10: in the source-pipeline portfolio a next-step card reads "Evidence date: Unknown · source_observed_scope". `frontend/src/lib/evidence-status.ts:170-182` puts the check `code` into the visible `context`; `components/evidence-status.tsx:180` prints it.
- Observed on the synthetic browser fixture on 2026-11-10: in zh-TW the sign-in page still shows "LOCAL-FIRST / SELF-HOSTED", "CSV -> SQLite -> ODS", "01 / OBSERVE", "02 / REVIEW", "03 / PRESERVE". They are literals at `frontend/src/App.tsx:212-218`.
- `frontend/src/App.tsx:226-228` prints the raw error code after the sign-in error message.

### Expected behaviour

- Holdings rows use the same translated label as the account list in every locale.
- A known check code shows a localized sentence; the raw code is inside the existing technical-details disclosure. An unknown code shows a generic localized title.
- Sign-in decoration is localized or marked decorative and language-neutral; the error message stands without a code.

### Scope

- In scope: the Web report view mapping for holdings rows; evidence item titles; sign-in strings.
- Out of scope: stored payloads, `combined.py`, report documents (PDF, ODS, Markdown), user or source supplied names, the generic Bitcoin wording planned for V2 (WL-P0-008, WL-P0-012C).

### Implementation notes

- `legacy_text` and the legacy key map are in `src/wealth_ledger/i18n.py` and `src/wealth_ledger/locales/legacy.json`. Read [i18n-plan.md](../docs/i18n-plan.md) first.
- `scripts/check_language.py` rejects new CJK text outside the catalogs. Put translations only in locale JSON files.
- User and source text is never translated.

## Acceptance criteria

- [ ] Given the synthetic combined report and en-CA, when Holdings loads, then no table cell contains CJK characters; in zh-TW and zh-CN the same cells use that locale.
- [ ] Given a holding whose name came from a source file, then its text is identical in every locale.
- [ ] Given a check with code `source_observed_scope`, then the item shows a localized sentence and the raw code appears only inside technical details.
- [ ] Given an unrecognized code, then a generic localized title is shown and the code is in details.
- [ ] Given zh-TW on the sign-in page, then no English sentence remains outside the brand name; a failed sign-in shows the message without a raw code.
- [ ] Saved report documents and fingerprints in existing tests are unchanged.

- Frontend unit test for a known and an unknown code.
- Browser assertion on the zh-TW sign-in page.
