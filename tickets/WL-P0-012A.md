# WL-P0-012A: Define the V2 analysis read contract for securities, crypto and total

## Goal

The three V2 analysis pages need one versioned read contract so they can be built in parallel with confidence and tested against fixed numbers. Today WL-P0-012 bundles this contract with all three pages. This child delivers only the endpoints and DTOs.

## Context

### Current behaviour

- No `/api/v2/analysis` route exists (`src/wealth_ledger/web_v2/api.py:26-37` lists all V2 routes).
- The shipped pages read a frozen report (`GET /api/v1/portfolios/{id}/reports/{report_id}`, `src/wealth_ledger/web/reports.py:293`); its DTO is edition-based and cannot refresh.
- Positions come from WL-P0-008 and quotes and FX from WL-P0-009.

### Expected behaviour

- `GET /api/v2/analysis/securities`, `/crypto` and `/total`, each taking `currency`.
- Every response carries: a calculation identifier, fact generation, valuation time, report currency, exact decimal strings in native and converted currency, `known_subtotal`, a nullable `complete_total`, source, quote and FX dates, and typed coverage or assumption codes.
- A KPI that cannot be computed is a typed "unavailable" status with a reason, never zero.
- Responses are tenant-scoped and cache keys include user, currency and generation.

### Scope

- In scope: the three endpoints, DTOs, OpenAPI, fixed-oracle tests.
- Out of scope: exposures (WL-P0-010), exports (WL-P0-013A), refresh scheduling (WL-P0-009), any page.

### Implementation notes

- DTO and error conventions: `src/wealth_ledger/web_v2/schemas.py`. Decimal rules: [canonical-domain.md](../docs/canonical-domain.md).
- Unknown is never zero and CAD, USD and TWD are alternative equivalents, never additive (AGENTS.md).
- The frontend types are generated: see `docs/web-frontend.md` lines 130-140 for `scripts/export_web_schema.py` and `openapi-typescript`. Decide whether V2 gets its own generated file.
- Acceptance numbers come from the golden cases referenced by WL-P0-008 and the original WL-P0-012 criteria.

### Owner decisions recorded 2026-11-10

- Each analysis response includes a daily value series revalued with fetched prices, not only import dates. Days without a price carry the last known price and are marked.
- Securities responses expose book cost and unrealized gain where the source provided cost, as a typed "unavailable" otherwise. Cash is a separate class and a separate line in Total.
- Crypto quantity is purchases minus sales reported by the same exchange file; the response says when sales were counted.
- Assets are classified by asset class, not institution. A Bitcoin ETF is in securities.
- MVP order (owner: a usable V2 as soon as possible): the first version may value securities from the import's own market values and Bitcoin from the existing live price, before WL-P0-009 delivers stock quotes. The decision below is answered yes. This ticket may therefore start after WL-P0-008 for that first version; stored live quotes follow in WL-P0-009B, more currencies in WL-P0-009C and the daily series in WL-P0-009D, each of which extends this contract.

## Acceptance criteria

- [ ] Given only a securities import, then `/securities` and `/total` match the fixed oracle right after the commit generation and `/crypto` reports "no eligible acquisitions" without a zero value.
- [ ] Given securities and Bitcoin acquisitions, then `/total` counts Bitcoin once and equals the oracle in each supported currency.
- [ ] Given a missing quote or FX rate, then `known_subtotal` is returned, `complete_total` is null and the affected rows carry a reason code.
- [ ] Given user A, then no parameter returns user B's data.
- [ ] OpenAPI lists the routes and every field; decimal values are strings.

### Tests

- Opt-in PostgreSQL tests with independently derived oracles.
- HTTP contract tests in the style of `tests/test_web_v2_api.py`.
