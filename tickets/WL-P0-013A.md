# WL-P0-013A: Render exports on demand from a pinned calculation

## Goal

V2 produces PDF, Excel, ODS and Markdown only when the user asks, from exactly the figures on screen. This child carries the service and routes of WL-P0-013; the download panel is WL-P0-013B.

## Context

### Current behaviour

- The shipped application renders report files during import publication (`src/kurafolio/source_publication.py`, `publishing.py`) and serves them as artifacts (`src/kurafolio/web/api.py:336-350`, `web/exports.py:130-137`).
- Renderers: `src/kurafolio/workbook.py`, `reporting.py`, `source_workbook.py`. They need no LibreOffice. The ODS writer builds the package with `zipfile` and `xml.etree` only (`workbook.py`); there is no Excel writer and no spreadsheet library in the lock files.
- No `/api/v2/exports` route exists.

### Expected behaviour

- `POST /api/v2/exports` with a calculation identifier, format, currency and locale creates a job; `GET` returns status; a completed job serves the file to its owner only.
- Formats for go-live, chosen by the owner on 2026-11-12: PDF, Excel (`.xlsx`), ODS and Markdown. CSV, JSON, PNG and ZIP are WL-P1-014.
- The Excel file carries the same sheets, values, formulas and number formats as the ODS file, and opens without repair in Microsoft Excel and LibreOffice.
- The file matches the pinned calculation even if newer prices arrive during rendering.
- Import and refresh create no export job or file.

### Scope

- In scope: service, routes, job handling, formula-injection escaping, an optional bounded private cache, tests.
- Out of scope: the panel UI (WL-P0-013B), legacy editions (WL-P0-020).

### Implementation notes

- Job and lease patterns: [postgres-foundation.md](../docs/postgres-foundation.md). Report contracts: [report-spec.md](../docs/report-spec.md), [workbook.md](../docs/workbook.md).
- Preserve the en-CA, zh-TW and zh-CN contracts, bundled fonts and unknown semantics (AGENTS.md).
- Write the Excel package the way the ODS writer works: standard library `zipfile` and XML, one shared table model feeding both spreadsheet writers so their figures cannot drift. Adding a spreadsheet library instead needs the lock files, `scripts/dependency_inventory.py --require-declared` and a reason in the PR.
- Native Excel charts are optional for go-live. If they are left out, each chart's data stays as a table on its sheet and the PR says so; file a follow-up ticket.
- Excel converts text that looks like a number or date. Write identifiers, symbols and account labels as strings.

## Acceptance criteria

- [ ] Given an import or a refresh, then no export job or file exists until a request is made.
- [ ] Given a pinned calculation and a later price change, then all four formats show the pinned figures.
- [ ] Given the same calculation, then the Excel and ODS files hold the same sheets and the same cell values; a test compares them cell by cell.
- [ ] The Excel file passes a structural check (content types, relationships, shared strings, well-formed XML) and opens without a repair prompt; the PR records the application and version used for the manual open.
- [ ] ODS charts and formulas and PDF pagination render in a clean environment without LibreOffice.
- [ ] Given another user's export identifier, then status and download are refused.
- [ ] Cells beginning with `=`, `+`, `-` or `@` from source text are escaped in ODS and Excel.
- [ ] Three locales produce complete documents in all four formats, with CJK text intact in the Excel file.
