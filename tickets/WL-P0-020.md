# WL-P0-020: Show the legacy report archive in the V2 app

## Goal

Owner decision 2026-11-11: V2 starts fresh and old reports are read in the old application, which stays untouched. This ticket is therefore optional and P2. If it is taken up, there is no migration to rely on: it would copy the old report files into a read-only V2 archive. The text below predates that decision.

After migration, a user's earlier saved report editions are history they must still be able to read and download. The V2 direction keeps them as an archive, but no ticket gives the user a way to open them, so cutover would strand years of reports in the old application.

## Context

### Current behaviour

- The shipped reader shows saved editions with grouped history and downloads (`frontend/src/components/report-reader.tsx`, `frontend/src/lib/report-library.ts`, routes at `src/kurafolio/web/reports.py:289-299`).
- WL-P0-014 migrates ledgers and reconciles "archived report bytes" but defines no read route or page for them.
- No V2 route serves archived editions (`src/kurafolio/web_v2/api.py:26-37`).

### Expected behaviour

- A contextual page, linked from App Settings, lists archived editions by valuation date and scope and opens each in the existing reader with its original downloads.
- Each archived edition is marked "archived, not updated" and states that live analysis uses a different scope.
- Bytes and wording are served unchanged; nothing is regenerated or revalued.

### Scope

- In scope: read-only archive routes for the signed-in user, the list and reader page, tests.
- Out of scope: migration itself (WL-P0-014), editing or deleting editions, mixing archived figures into live analysis.

### Implementation notes

- Reuse `ReportReader` and `groupEditions`; they already handle legacy and migration-capture editions ([web-legacy-reports.md](../docs/web-legacy-reports.md), [web-analysis-reports.md](../docs/web-analysis-reports.md)).
- Never rewrite old manifests or weaken modern verification (AGENTS.md).
- This ticket holds both a small read contract and a page because the page is a port of an existing component. Split it if the owner chooses option (b) below.

## Acceptance criteria

- [ ] Given a migrated user with three archived editions, then the archive lists three entries grouped by date and scope.
- [ ] Given an archived edition, then its document, tables, charts and three downloads are byte-identical to the pre-migration files.
- [ ] Given a user with no archive, then the Settings link is absent.
- [ ] Given user A, then no request returns user B's editions.
- [ ] Each page states that the edition is archived and not updated.
- [ ] Keyboard reachable with visible focus, one `h1`, labelled controls, chart data available as a table, no colour-only meaning; en-CA, zh-TW, zh-CN; light and dark; 375 px and 1024 px.

### Tests

- Port the relevant cases of `frontend/tests/browser/report-reader.spec.ts` to the V2 route.
- Authorization and byte-equality tests on the read routes.
