# WL-P0-007L: Add prepare-lease worker functions: read_plan_basis_v1 and prepare_preview_v1

## Goal

Give the worker the two calls it needs to turn admitted stages into a review. `read_plan_basis_v1` returns pinned pages of the set's inputs, Plan scope and source pins, decisions, and accepted entities, mappings, revisions, heads and authorities. `prepare_preview_v1` checks a ReviewBundle against exactly those stages, decisions and generations, stores one immutable preview, and moves the set to NEEDS_MAPPING, CONFLICT or READY. Both run only under an active prepare lease issued by `claim_plan_v1` (WL-P0-007C).

## Acceptance criteria

- [ ] Both functions match their r7 inventory signatures, revoke PUBLIC and authenticate through `_guard_worker_v1` plus the exact active prepare lease, fence, realm and originating session.
- [ ] `read_plan_basis_v1` regenerates byte-identical pages under unchanged pins, writes no lease cache field, bounds pages to 50 rows and 4 MiB + 16 KiB without truncating a row, and returns `import_stale` when any pinned generation, fence or expiry changes. The `large-basis-page.json` vector reproduces exactly.
- [ ] `prepare_preview_v1` enforces every check `validate_review_bundle` makes, plus the stored stages, current decisions revision, generations and reservation bytes; it stores one immutable preview and replays an identical request as `already_prepared`.
- [ ] Opt-in PostgreSQL tests cover each refusal without partial writes.
