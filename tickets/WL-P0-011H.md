# WL-P0-011H: Show source-aware Stock/Bond and Crypto pages

## Goal

Make the V2 shell decide from real data whether Stock/Bond, Exposures and Crypto show content or offer "Enable a source". This is the second half of a WL-P0-011A acceptance criterion. The owner moved it here on 2026-11-12 so the shell could close before the positions contract exists.

## Context

### Current behaviour

- WL-P0-011A (PR #48) shows "Enable a source" on Stock/Bond, Exposures and Crypto every time. All eight destinations stay in the navigation.
- The shell cannot read holdings. The positions read contract is WL-P0-008.
- The V2 source catalog (`GET /api/v2/sources`, `CatalogItem` in `src/kurafolio/web_v2/schemas.py`) carries no asset class. Nothing tells the shell whether a source supplies securities or crypto.

### Expected behaviour

- With no securities source enabled and no securities holdings, Stock/Bond and Exposures offer "Enable a source". Crypto does the same for crypto.
- Holdings from a source that has since been disabled still count. The page shows them, and the destination stays reachable.
- Unknown is not zero. While the holdings request is loading or fails, the page shows the shared loading or error state, not the offer.

### Scope

- In scope: an `asset_classes` field on the source catalog item, the holdings and source checks that drive these three pages, and the browser tests against a mocked `/api/v2`.

### Owner decision recorded 2026-11-12

- Each plugin declares the asset classes it can produce (`securities`, `crypto`, or both) and the catalog returns them. A destination offers "Enable a source" only when no enabled source declares its class **and** the WL-P0-012A analysis read for that class has no holdings. Holdings already imported always count, even from a disabled source.

### Implementation notes

- The catalog DTO is `CatalogItem` in `src/kurafolio/web_v2/schemas.py`; the plugin metadata it is built from is described in [web-v2-sources.md](../docs/web-v2-sources.md). Add the field as a closed, ordered list; a plugin that declares nothing is treated as declaring nothing, not as both.
- Holdings presence comes from the WL-P0-012A reads (`GET /api/v2/analysis/securities` and `/crypto`), which classify by asset class, not by institution. A Bitcoin ETF is a security.
- Out of scope: the page content itself (WL-P0-012B, WL-P0-012C) and the Parser Plugin Store page (WL-P0-011C).

## Acceptance criteria

- [ ] Given no securities source and no securities data, then Stock/Bond and Exposures offer "Enable a source". Given no crypto source and no crypto data, Crypto offers it.
- [ ] Given holdings from a disabled source, then the matching destination shows them and stays reachable.
- [ ] Given a pending or failed holdings request, then the page shows the shared loading or error state, never the offer.
- [ ] Given a newly enabled crypto source and no import yet, then Crypto no longer offers "Enable a source" and shows the empty state that leads to import.
- [ ] The catalog returns `asset_classes` for each bundled plugin; an API test covers both bundled plugins.
- [ ] en-CA, zh-TW and zh-CN; the existing V2 shell browser cases still pass.
