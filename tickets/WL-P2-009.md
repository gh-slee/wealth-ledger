# WL-P2-009: Add dependency vulnerability and static security scanning to CI

## Goal

CI verifies dependency licences but not known vulnerabilities, and runs no static security analysis. The application handles sign-in, sessions and financial records for several users on one instance. Add scheduled and pull-request scanning so a vulnerable pinned dependency or an obvious injection pattern is reported.

## Context

### Current behaviour

- `.github/workflows/ci.yml` runs `scripts/dependency_inventory.py --require-declared`, which inventories licences offline ([web-release-acceptance.md](../docs/web-release-acceptance.md)).
- No job runs a vulnerability audit of the Python lock files or `frontend/package-lock.json`, and no code-scanning workflow exists under `.github/workflows/`.
- Dependencies are hash-pinned in `requirements*.lock`, so nothing updates them automatically.

### Expected behaviour

- A weekly scheduled job and a pull-request job audit the Python lock files and the npm lock file against a public advisory database and fail on high-severity findings without a recorded exception.
- Static analysis for Python and TypeScript runs on pull requests and reports findings in the repository's security view.
- Exceptions are a reviewed file in the repository with an expiry date per entry.

### Scope

- In scope: the two scans, the exception file, documentation in `SECURITY.md`.
- Out of scope: automatic dependency update pull requests, container image scanning (UX-P1-007), secret scanning settings (owner action).

### Implementation notes

- Audit tools are development-only and must not enter `requirements.lock` or the runtime image.
- Scheduled jobs need network access to the advisory database; unit tests must stay offline.
- Keep `permissions` minimal; code scanning needs `security-events: write` on that job only.

## Acceptance criteria

- [ ] Given a lock file pinned to a version with a known high-severity advisory (on a test branch), then the audit job fails and names the package.
- [ ] Given an exception entry with a future expiry, then that finding does not fail the job; after expiry it does.
- [ ] Static analysis results appear for a pull request.
- [ ] `python scripts/dependency_inventory.py --require-declared` still passes and the runtime image is unchanged.

### Tests

- The demonstration branch with a vulnerable pin, linked in the PR and then deleted.
