# WL-P0-011F: Add the V2 App Settings and Profile pages

## Goal

Two of the eight approved destinations, App Settings and User Profile, have no ticket. A signed-in V2 user needs one place for personal preferences and password, and one for data and analysis settings with links to import history and operator guidance.

## Context

### Current behaviour

- The V2 shell exists (WL-P0-011A, `frontend/src/v2/shell.tsx`, shared states in `frontend/src/v2/page-state.tsx`), with setup, login and invitations (WL-P0-011B, `frontend/src/v2/auth-pages.tsx`, `invitations.tsx`). The V2 API client is `frontend/src/v2/api.ts`.
- The shipped Settings page (`frontend/src/App.tsx:589-715`) mixes report language, Bitcoin cost policy and password under a portfolio-scoped route. Its password form has one new-password field and ends with an unrelated sentence.
- V2 routes available: `GET /api/v2/me` (`web_v2/api.py:328`), `POST /api/v2/auth/password` (`:346`, new password at least 15 characters, `schemas.py:23`). Preferences arrive with WL-P0-011E.

### Expected behaviour

- Profile (`/app/profile`): username (read-only), interface language, time zone, default reporting currency, appearance, change password (current, new, repeat), and a short "Forgot your password?" note saying reset is a host operation.
- App Settings (`/app/settings`): reporting defaults, links to source connections, import history and the legacy archive when present; for the instance admin a clearly separated block linking to backup, restore and installation guidance. No second-portfolio control.
- Saving shows success in place; a stale revision reloads the values and says so.
- Loading keeps the page structure and never shows 0 before a response. Empty, partial, stale and error states each state what is missing and offer one next action.

### Scope

- In scope: the two pages, their forms, locale keys, browser tests.
- Out of scope: invitation management (WL-P0-011B), source enablement (WL-P0-011C), backup operations in the browser (UX-P2-004), a session list.

### Implementation notes

- Reuse `frontend/src/components/data-table.tsx`, `chart.tsx`, `ui/button.tsx`, `lib/format.ts`, `lib/i18n.tsx`, `lib/theme.tsx` and the tokens in `frontend/src/styles.css`. Read [DESIGN.md](../DESIGN.md), [PRODUCT.md](../PRODUCT.md) and [web-frontend.md](../docs/web-frontend.md).
- Browser tests intercept `/api/v2` with Playwright `page.route`, as `frontend/tests/browser/onboarding.spec.ts` does for `/api/v1`, until a synthetic V2 fixture exists.
- Add locale keys to all three catalogs in one block named for this ticket; rebase before the PR.
- Changing interface language applies at once and is saved; appearance stays in `localStorage` through `lib/theme.tsx`.
- Password rules must match the server: 15 to 256 characters.

## Acceptance criteria

- [ ] Given a signed-in user, when they change language, time zone or currency and save, then a reload on a fresh browser profile shows the saved values.
- [ ] Given two different new-password entries or fewer than 15 characters, then submit is blocked with a message linked to the field.
- [ ] Given a successful password change, then the user is told other sessions were ended.
- [ ] Given a member account, then the operator block is absent; given the instance admin, it is present and contains links only.
- [ ] Given the preferences request fails, then the form keeps the entered values and offers retry.
- [ ] Keyboard reachable with visible focus, one `h1`, labelled controls, chart data available as a table, no colour-only meaning; en-CA, zh-TW, zh-CN; light and dark; 375 px and 1024 px.
