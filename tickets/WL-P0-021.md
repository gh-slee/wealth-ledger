# WL-P0-021: Provide a one-command V2 MVP deployment for a self-hosted instance

## Goal

The owner wants to use V2 for real as soon as the MVP works and give feedback from daily use. Today nothing starts a complete V2 instance: there is a PostgreSQL-only compose file and a V2 server command with many required arguments. Provide one documented way to start database, V2 API with the bundle, and import worker on a new empty instance.

## Context

### Current behaviour

- `compose.pg-foundation.yaml` starts PostgreSQL only and says it is an optional development foundation.
- `compose.yaml` runs the SQLite application (`web` and `worker` services, port 8000).
- `python -m wealth_ledger.web_v2 serve` needs explicit secret files, origin, host, port and `--schema-profile` (`src/wealth_ledger/web_v2/__main__.py:13-22`); migrations are separate operator commands ([postgres-foundation.md](../docs/postgres-foundation.md), [web-v2-identity.md](../docs/web-v2-identity.md)).
- The import worker and the 0004 migration do not exist yet (WL-P0-007F, WL-P0-007D).

### Expected behaviour

- A separate compose file for V2 with PostgreSQL, the V2 API serving the bundle, and the import worker, bound to loopback, on its own volume and its own port so it never touches a SQLite instance.
- A documented first-run sequence: create secrets, run migrations, create the first administrator, start. Each step is one command.
- Stop, start and upgrade keep data. A backup and an empty-target restore procedure are documented and tested on synthetic data.
- The page gallery or README gains a short "Run the V2 MVP" section that states what the MVP does and does not do.

### Scope

- In scope: compose file, first-run script or documented commands, container hardening equal to `compose.yaml`, a synthetic smoke test, documentation.
- Out of scope: public image publication (UX-P1-007), migration of existing SQLite data (WL-P0-014), release acceptance across platforms (WL-P0-015).

### Implementation notes

- Copy the hardening of `compose.yaml`: read-only root, dropped capabilities, no-new-privileges, memory and PID limits, loopback port.
- Reuse `scripts/postgres.py` and `scripts/docker_context.py`; the image must stay source-only and reproducible.
- Secrets are files, never environment values or arguments (AGENTS.md, web-v2-identity.md).
- Use the claim's `isolation_id` and `port_base` for every test container and volume. Never start against, or share a volume with, an existing instance.

## Acceptance criteria

- [ ] Given a clean machine with Docker, when the operator follows the documented steps, then a V2 instance answers on its loopback port and the setup page loads in a browser.
- [ ] Given the instance is stopped and started, then accounts and imported data remain.
- [ ] Given a backup taken with the documented command, then it restores into a second empty instance and sessions are revoked there.
- [ ] The V2 compose project uses names, volumes and ports distinct from `compose.yaml`; starting one never affects the other.
- [ ] A synthetic end-to-end smoke test (register, enable a source, import the example holdings file, read the securities page) passes in CI or as an opt-in Docker test.
- [ ] The documentation lists what the MVP leaves out.

### Tests

- Opt-in Docker test in the style of `tests/test_web_docker.py`.
- The smoke test above.
