# UX-P2-007: Tidy empty, not-found and settings states in the current shell

## Goal

Several small states mislead: an unknown page silently shows the Overview, an unknown portfolio offers a retry that can never work, every analysis page of an empty portfolio repeats the full first-run guide under an inert currency selector, the password form has no confirmation, and Settings ends with a sentence about an unrelated feature.

## Context

### Current behaviour

- Observed on the synthetic browser fixture on 2026-11-10: `/app/<portfolio>/nonexistent-page` renders the Overview and keeps the path. `frontend/src/App.tsx:363` falls back to `"overview"`.
- Observed on the synthetic browser fixture on 2026-11-10: an unknown portfolio ID shows "The request failed. Check the details and try again." with "Try again" (`App.tsx:495-512`).
- Observed on the synthetic browser fixture on 2026-11-10: Holdings, Exposure, History and Bitcoin of an empty portfolio each render the whole first-run guide (`App.tsx:576-581`) and Overview, Holdings and History still show the currency selector (`App.tsx:440-454`).
- Observed on the synthetic browser fixture on 2026-11-10: "Change password" has one new-password field (`App.tsx:697-705`); recovery from a typo is a host command.
- Observed on the synthetic browser fixture on 2026-11-10: Settings ends with "Use Financial records for BTC events and contributions. Existing-ledger adoption remains a trusted-host CLI operation." (`App.tsx:712`, key `maintenance`), also used on the Bitcoin page (`analysis.tsx:587`).

### Expected behaviour

- Unknown page: a "Page not found" panel with a link to the Overview.
- Unknown or inaccessible portfolio: "Portfolio not found" with a link to the portfolio list; no retry.
- Empty portfolio: the full guide on Overview only; other analysis pages show one sentence and a link to it. No currency selector without a report.
- Password change asks for the new password twice and blocks submit on mismatch.
- Settings has no unrelated footnote; it names where backup and restore are documented instead.

### Scope

- In scope: the five states above.
- Out of scope: portfolio rename or delete (V2 has one portfolio), backup UI (UX-P2-004), the V2 shell.

### Implementation notes

- The API returns 404 with code `not_found` for an unknown portfolio; branch on `ApiError.status` in `frontend/src/lib/api.ts`.
- Keep the Bitcoin page sentence; only Settings changes.
- New locale keys in one block named for this ticket.

## Acceptance criteria

- [ ] Given an unknown page segment, then a not-found panel is shown with a working link and the heading is not "Overview".
- [ ] Given an unknown portfolio ID, then "Portfolio not found" is shown with a link and no retry button.
- [ ] Given an empty portfolio, when Holdings loads, then one sentence and a link to the Overview guide are shown and no currency selector.
- [ ] Given two different new-password entries, then submit is blocked with an inline message linked to the field.
- [ ] Settings no longer shows the adoption sentence and links to the backup guide.
- [ ] Three locales; keyboard reachable; messages use `role="alert"` or `role="status"` as today.

### Tests

- Extend `frontend/tests/browser/onboarding.spec.ts` (empty pages, not-found) and `workflow.spec.ts` (password mismatch).
