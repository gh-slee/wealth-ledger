# WL-P0-007J: Decide where read and control rate limits are admitted

## Goal

r7 declares shared PostgreSQL rate buckets for reads (60/600 per 300 s, user/instance)
and control calls (30/300), and forbids replacing them with per-process counters.
`_quota_v1` implements both buckets, but nothing can consume them: no gateway function
calls `_quota_v1` for `read` or `control`, and the helper is owner-only, so the API
role cannot call it either. docs/web-v2-imports.md says rate admission "is left to the
caller", but no caller has a path to it. The owner needs to choose where admission
happens before WL-P0-007D grants roles and WL-P0-007E wires routes.

## Acceptance criteria

- [x] The owner records a choice below.
- [x] The SQL gateway admits one attempt to the selected PostgreSQL bucket when called in its own transaction. WL-P0-007E applies it to create, decide, cancel, confirm and all four reads.
- [x] Opt-in PostgreSQL tests show exhaustion returns `import_busy` and a refused attempt still counts.

## Plan

- [x] Get the owner decision.
- [x] Implement the SQL gateway function and add PostgreSQL tests.
- [x] Update docs/web-v2-imports.md.

This adds one function to the function inventory, which the owner approved with this answer. The financial transaction's lock order and the lock-free reads stay as they are.
