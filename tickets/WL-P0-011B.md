# WL-P0-011B: Add V2 setup, login and invitation UI

## Goal

Browser UI for the V2 identity backend: protected first setup, registration from an invitation, sign-in, and invitation management for the instance admin. A new user must be able to go from an invitation link to a signed-in empty account without touching a terminal.

## Context

### Current behaviour

- No V2 page exists. The shipped UI talks only to `/api/v1` (`frontend/src/lib/api.ts`).
- Backend (merged, WL-P0-005): `POST /api/v2/auth/setup` (`src/kurafolio/web_v2/api.py:310`), `/auth/register` (`:316`), `/auth/login` (`:322`), `GET /api/v2/me` (`:328`), `/auth/logout` (`:339`), `/auth/password` (`:346`), `POST` and `GET /api/v2/admin/invitations` (`:361`, `:365`), `POST .../{id}/revoke` (`:377`).
- DTOs in `src/kurafolio/web_v2/schemas.py`: `Setup` and `Register` need a token, a username and a password of 15 to 256 characters (`:52-61`); `Invitation.status` is `issued | expired | revoked | consumed` (`:115-121`); `Me.user.role` is `instance_admin | member` (`:99-102`).
- The shipped sign-in page (`frontend/src/App.tsx:198-265`) says "Use the owner account initialized on your host" and shows a raw error code after the message.
- Password reset and account enable or disable are host-only ([web-v2-identity.md](../docs/web-v2-identity.md)).

### Expected behaviour

- First setup `/setup?token=...`: username, password twice; on success go to sign-in. Without a valid token the page explains that setup is started by the operator.
- Registration `/register?token=...`: same fields. An expired, revoked or consumed invitation shows a distinct message and no form.
- Sign-in `/login`: username and password; failure shows one message without codes; a "Forgot your password?" note says reset is a host operation.
- Invitations (admin only, under Profile or Settings): issue one, show its link once with a copy button and expiry, list invitations with status, revoke an issued one after confirmation.
- Sign-out and session expiry clear all cached data and return to sign-in with a clear message.

### Scope

- In scope: the four screens, their states, locale keys, browser tests.
- Out of scope: public self-registration, e-mail, password reset in the browser, Profile and Settings pages (WL-P0-011F).

### Implementation notes

- Reuse `frontend/src/components/data-table.tsx`, `chart.tsx`, `ui/button.tsx`, `lib/format.ts`, `lib/i18n.tsx`, `lib/theme.tsx` and the tokens in `frontend/src/styles.css`. Read [DESIGN.md](../DESIGN.md), [PRODUCT.md](../PRODUCT.md) and [web-frontend.md](../docs/web-frontend.md).
- Browser tests intercept `/api/v2` with Playwright `page.route`, as `frontend/tests/browser/onboarding.spec.ts` does for `/api/v1`.
- Add locale keys in a block named for this ticket to reduce merge conflicts; rebase before the PR.
- Mirror the cache-clearing sign-out and expiry handling of `frontend/src/App.tsx:125-136,175-191` and `clearTransport` in `lib/api.ts`.
- The invitation token is shown once by the server (`InvitationIssued`, `schemas.py:124-128`); never store it in browser storage or a URL the app keeps.
- The longer draft spec is in the local planning package until WL-P0-016 publishes it. This ticket is written to be sufficient without it.

### Owner decisions recorded 2026-11-10

- Registration is invite-only by default. An administrator switch that opens self-registration is wanted for instances meant for the public; the backend has only invitation-based registration today (`src/kurafolio/web_v2/api.py:316`), so the switch is a follow-up after the MVP and is out of scope here.
- One instance serves multiple users.

## Acceptance criteria

- [x] Given a valid setup token, when the operator submits a username and a matching password of at least 15 characters, then the instance is initialized and sign-in is shown.
- [x] Given two different password entries or fewer than 15 characters, then submit is blocked with a message linked to the field.
- [ ] Given an expired, revoked or consumed invitation, then a distinct message is shown and no form. (Partial: the API reports all three, and a taken username, as `registration_rejected` after submit, so the form stays with one message naming both causes. Follow-up WL-P0-011I.)
- [x] Given wrong credentials, then one localized message is shown, the password field is cleared and no error code is visible.
- [x] Given an instance admin, when they issue an invitation, then its link and expiry are shown once with a copy control; the list shows its status; revoking asks for confirmation and updates the status.
- [x] Given a member, then invitation management is absent and its routes are never requested.
- [x] Given sign-out, session expiry or a different user signing in, then no data from the previous session is rendered or kept in memory.
- [x] Keyboard reachable with visible focus, one `h1` per page, labelled controls, no colour-only meaning; en-CA, zh-TW, zh-CN; light and dark; 375 px and 1024 px.
