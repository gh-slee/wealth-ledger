# WL-P0-011C: Add source enablement and connection UI

## Goal

Browser UI to see which data sources are installed, enable an exact version for the signed-in user, and manage file-import connections. Two sources exist today, so this is a short list with enable controls and a link to the authoring guide, not a storefront. Absorbs the useful parts of UX-P1-006.

## Context

### Current behaviour

- No V2 page exists. The shipped UI talks only to `/api/v1` (`frontend/src/lib/api.ts`).
- Backend (merged, WL-P0-006, explicit sources profile only): `GET /api/v2/sources`, `PUT /api/v2/sources/{plugin_id}/capabilities/{capability}`, `GET` and `POST /api/v2/source-connections`, `GET` and `PUT /api/v2/source-connections/{id}` (`src/kurafolio/web_v2/api.py:412-437`).
- DTOs in `src/kurafolio/web_v2/schemas.py`: `CatalogItem` (`:251-257`) has display name, publisher, docs URL and up to two capabilities; `Capability.status` is `DISABLED | CONFIRMATION_REQUIRED | UNAVAILABLE | ENABLED` (`:246`); every mutation carries an operation ID, expected revision and realm (`:192-195`).
- Lifecycle rules: [web-v2-sources.md](../docs/web-v2-sources.md). Catalog metadata is inert; enabling a source imports nothing.
- The shipped app has no source screen; parsers are chosen inside the import form.

### Expected behaviour

- Parser Plugin Store `/app/sources` (name confirmed by the owner): a simple list with enable switches, one row per installed source with name, publisher, supported formats and versions, capability (File, API) and status. API capability shows "planned" until a real connector exists.
- Enable or disable per capability with one control. `CONFIRMATION_REQUIRED` asks the user to confirm the newer installed version. `UNAVAILABLE` explains that the operator must install or repair it.
- Connections for an enabled file capability: add with a label and optional alias, rename, disable. Disabling keeps existing data readable.
- Only official plugins are offered: those reviewed and merged in the repository and installed by the operator (owner decision 2026-11-10). Users cannot add or upload their own. A link to the contribution guide ([parser-sdk.md](../docs/parser-sdk.md)) explains how to propose a new plugin through a pull request.
- A stale revision reloads the list and tells the user their change was not applied.

### Scope

- In scope: the list, enable and disable, connection management, locale keys, tests.
- Out of scope: installing plugins, credentials or API sync (WL-P1-001), the authoring tutorial content (WL-P1-003), import (WL-P0-011D).

### Implementation notes

- Reuse `frontend/src/components/data-table.tsx`, `chart.tsx`, `ui/button.tsx`, `lib/format.ts`, `lib/i18n.tsx`, `lib/theme.tsx` and the tokens in `frontend/src/styles.css`. Read [DESIGN.md](../DESIGN.md), [PRODUCT.md](../PRODUCT.md) and [web-frontend.md](../docs/web-frontend.md).
- Browser tests intercept `/api/v2` with Playwright `page.route`, as `frontend/tests/browser/onboarding.spec.ts` does for `/api/v1`.
- Add locale keys in a block named for this ticket to reduce merge conflicts; rebase before the PR.
- Send `operation_id`, `expected_revision` and `expected_realm` exactly as the DTOs require; generate the operation ID once per user action so a retry is idempotent.
- Tests and fixtures to read: `tests/test_web_v2_sources.py`, `tests/fixtures/source_capabilities/`.
- The longer draft spec is in the local planning package until WL-P0-016 publishes it. This ticket is written to be sufficient without it.

## Acceptance criteria

- [x] Given two installed sources, then both are listed with versions, capabilities and status, and nothing uninstalled is shown.
- [x] Given a disabled file capability, when the user enables it, then its status becomes Enabled and Import Data offers it (verified with WL-P0-011D or a mock).
- [x] Given `CONFIRMATION_REQUIRED`, then the user is asked to confirm the named version before it is used.
- [x] Given the user disables a source that has data, then a confirmation states that existing data stays visible and new imports stop.
- [x] Given a stale revision response, then the list reloads and a message says the change was not applied.
- [x] Given an `UNAVAILABLE` capability, then no enable control is offered and the reason is stated.
- [x] A retry after a network failure sends the same operation ID.
- [x] Keyboard reachable with visible focus, one `h1` per page, labelled controls, no colour-only meaning; en-CA, zh-TW, zh-CN; light and dark; 375 px and 1024 px.
