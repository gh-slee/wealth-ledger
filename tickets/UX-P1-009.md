# UX-P1-009: Keep the selected report edition while navigating and the currency across reloads

## Goal

A user who selects an older report edition and then opens another page is returned to the latest edition with no notice, so figures on the two pages belong to different editions. Separately, the display currency returns to CAD on every reload. Keep both for the session within one portfolio.

## Context

### Current behaviour

- Observed on the synthetic browser fixture on 2026-11-10: with two editions, selecting the older one on Overview sets `?report=<id>`; clicking Holdings in the sidebar gives an empty query string and the selector shows the latest edition.
- Observed on the synthetic browser fixture on 2026-11-10: USD selected on Overview is still selected on Holdings (same mounted component), and is CAD again after a reload.
- `frontend/src/App.tsx:321-324` reads the edition from the `report` search parameter; sidebar links at `:396` navigate to `/app/<portfolio>/<page>` without the search string.
- `frontend/src/App.tsx:299` holds the currency in component state that starts at `"CAD"`. `PortfolioWorkspace` is keyed by portfolio (`:280`), so a portfolio switch also resets it. That reset is intended.

### Expected behaviour

- The selected edition follows the user across all sidebar destinations of one portfolio.
- When the selected edition is not the newest, every analysis page shows a notice naming its valuation cutoff with a "Back to latest" control.
- The currency survives a reload through a `currency` URL parameter.
- Switching portfolio or signing out clears both.

### Scope

- In scope: sidebar links, the currency selector, the earlier-edition notice.
- Out of scope: `localStorage` for anything financial; which pages offer the currency selector; V2 routes.
- Non-goals: remembering selections across portfolios. [web-frontend.md](../docs/web-frontend.md) requires selections to clear on logout and switch.

### Implementation notes

- Build the sidebar `to` from the current search parameters, limited to `report` and `currency`.
- Validate `currency` against `CAD | USD | TWD`; ignore anything else.
- Deep links tested in `frontend/tests/browser/report-reader.spec.ts` must keep working.
- The notice needs locale keys in the three catalogs; keep them in one block named for this ticket.

## Acceptance criteria

- [ ] Given two editions and the older one selected on Overview, when the user opens Holdings, Exposure, History, Bitcoin and Reports from the sidebar, then each shows the older edition and the URL keeps `report=<id>`.
- [ ] Given an edition other than the newest is selected, then each analysis page shows the notice and its control returns to the latest edition and removes the parameter.
- [ ] Given USD is selected, when the page is reloaded, then USD is still selected.
- [ ] Given `currency=XYZ` in the URL, then CAD is used and no error is shown.
- [ ] Given the user switches portfolio or signs out and in, then neither selection carries over.
- [ ] The notice is announced once (`role="status"`) and its control is keyboard operable.

### Tests

- New browser test in `frontend/tests/browser/report-reader.spec.ts` covering criteria 1, 3 and 5.
- Unit test for the parameter filter.

## Plan
