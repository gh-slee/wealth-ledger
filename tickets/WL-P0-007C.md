## Acceptance criteria

- [ ] `claim_plan_v1(work_kind=cleanup)` selects deterministically and never double-claims.
- [ ] `cleanup_set_v1` purges via `_purge_v1`, records proofs and releases the reservation.
- [ ] Failed or pending cleanup keeps a retryable state and never drops proof.
- [ ] (from WL-P0-007K) Terminal cleanup releases each raw slot still held by a fenced member attempt exactly once, after it proves that attempt has no live child or raw buffer.
- [ ] (from WL-P0-007K) A slot already released by `finish_member_v1` is never released again.
- [ ] (from WL-P0-007K) Opt-in PostgreSQL tests cover cancel during reception, cancel before claim, expiry before claim, and cancel after a finished attempt.

## Decisions needed

All six were answered by the owner on 2026-11-10: each recommendation is accepted.

1. `leases.session_digest` for a cleanup lease: a fixed cleanup-marker digest.
2. `LeaseAck.source_fingerprint` for a cleanup lease: the set digest.
3. Fence numbering: 1 plus the number of earlier cleanup leases for that set.
4. `cleanup_proofs` cover every normalize attempt that reached the launcher.
5. Pending or failed proof: keep `cleanup_state=failed` and hold the reservation until a proof succeeds.
6. Selection order: the oldest terminal set with cleanup pending or failed and no live cleanup lease.
