# WL-P0-015: Prove V2 release readiness and operational documentation

## Goal

Before V2 is called released, someone other than the people who built it checks that it does what the documents say, on the machine the owner actually uses, and that the documents say only what was checked. This ticket is that check. It produces evidence and corrected documentation, not features.

## Context

### Current behaviour

- CI runs seven jobs on Linux. The import SQL tests join them in WL-P0-022 and a V2 browser suite in WL-P0-023 ([CI_E2E_ASSESSMENT.md](CI_E2E_ASSESSMENT.md)).
- [web-release-acceptance.md](../docs/web-release-acceptance.md) describes upgrade, rollback, capacity, crash and platform evidence for the shipped SQLite application only.
- The README, [capability-status.md](../docs/capability-status.md), the user manual and the README screenshots describe the shipped application.
- WL-P0-021 documents starting, backing up and restoring a V2 instance.

### Owner decision recorded 2026-11-11

The release is verified on one platform: an Apple Silicon Mac with Docker Desktop. Linux amd64 is covered by CI only. Linux arm64 and Windows are not claimed. Decision OD-11 is answered.

### Expected behaviour

- A V2 section in [web-release-acceptance.md](../docs/web-release-acceptance.md) with dated evidence, on an Apple Silicon Mac with Docker Desktop, for: install from a clean checkout; first run; stop and start with data kept; upgrade from the previous V2 schema with data kept; backup and restore into an empty second instance with sessions revoked; restart of each service while an import is running; and what the instance does when the price provider is unreachable.
- A coverage table that maps each golden case G01 to G19 to the automated test that checks it, or says "not covered" with the reason. Expected values in those tests are written independently of the production calculation.
- An independent acceptance pass over the paths where a mistake costs the user money or privacy: totals and currency conversion, one user never seeing another's data, import commit and recovery, the refresh process, exports.
- The README, capability-status, the user manual and the operator guide describe V2 as merged: what it does, what it does not do, the supported platform, and the limits found by this ticket. The README screenshots are refreshed from synthetic V2 data ([screenshot guide](../assets/readme/README.md#when-to-refresh-screenshots)).
- Every platform, version or behaviour that was not tested is listed as not claimed.

### Scope

- In scope: the evidence runs, the coverage table, missing tests found by the table, documentation, screenshots.
- Out of scope: publishing an image or a release (UX-P1-007 and a separate owner approval), deploying anything, the owner's own move to V2 (WL-P0-014 guide), new features.

### Implementation notes

- The acceptance pass must be done by a session that implemented none of the tickets it checks. Record which session checked what.
- Use only synthetic data and the claim's `isolation_id` and `port_base`. Never start, upgrade or restore a real instance.
- Latency and resource figures: record what is measured on the test machine for a synthetic portfolio of 50 holdings and five years of daily history, with the machine description. Do not state a target that was not measured.
- "Upgrade from the previous schema" needs a saved synthetic database at the schema of the MVP release; create it in this ticket if no earlier ticket did.
- If the agent's environment cannot run Docker Desktop on an Apple Silicon Mac, it prepares the scripts and the checklist and reports that the platform evidence is not collected; it does not substitute another platform.

## Acceptance criteria

- [ ] Each of the seven operations listed above has a dated entry with the commands run, the result and the machine, or is listed as not verified with the reason.
- [ ] The golden-case table covers G01 to G19; every "covered" entry names a test that passes in CI or in a documented opt-in run.
- [ ] Given two users with the same provider identifiers, then no API route, export, cache or job returns one user's data to the other (golden case G16).
- [ ] Given a service killed during an import, then after restart the import is either committed once or not at all, and the user can retry (golden case G15).
- [ ] The README, capability-status, user manual and operator guide contain no statement about V2 that the evidence does not support, and name Apple Silicon Mac with Docker Desktop as the verified platform.
- [ ] README screenshots show V2 pages from synthetic data, as the screenshot guide requires.
- [ ] No push to a registry, release or deployment happens in this ticket.
