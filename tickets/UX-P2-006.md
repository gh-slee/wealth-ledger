# UX-P2-006: Separate cash from securities in Holdings and label each money column

## Goal

The Holdings table lists cash balances as securities with an average cost of 1.00 and an unrealized profit of 0.00, and mixes the display currency with each holding's own currency in one row without saying so. A reader cannot tell at a glance which numbers can be compared.

## Context

### Current behaviour

- Observed on the synthetic browser fixture on 2026-11-10: cash rows show symbol "CAD", name "CAD", average cost CA$1.00, unrealized P/L CA$0.00. A USD holding reads US$20.00 average cost, CA$187.50 market value, US$25.00 unrealized P/L.
- `frontend/src/components/analysis.tsx:189-195` filters out only `security_type === "CRYPTO"`, so cash rows stay.
- Columns at `analysis.tsx:214-238`: `avg_cost` and `unrealized_native` are formatted in the row currency; market value in the display currency with the header suffix "· CAD".

### Expected behaviour

- Securities table without cash rows. Cash listed below it as "Cash by account" with account, currency and balance in native and display currency.
- Headers say "Average cost (native)", "Market value (CAD)", "Unrealized P/L (native)".
- The holdings count excludes cash.

### Scope

- In scope: the Holdings page presentation.
- Out of scope: payload changes, valuation, the V2 securities page (WL-P0-012B carries the same rule).

### Implementation notes

- Identify cash by the field the payload already provides; inspect `Models["Holding"]` in `frontend/src/lib/schema.d.ts` and confirm on the fixture before choosing. If no reliable field exists, stop and record it in Handoff.
- Keep search, account and currency filters working for both tables.

## Acceptance criteria

- [ ] Given the synthetic report, then the securities table contains no cash row and the count matches.
- [ ] Given cash in three accounts, then "Cash by account" lists each with native and display amounts.
- [ ] Each money column header states whether it is native or the display currency.
- [ ] Sorting and filters work as before; both tables have distinct captions.
- [ ] Three locales.
