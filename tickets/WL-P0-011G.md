# WL-P0-011G: Serve the frontend bundle from the V2 backend

## Goal

A V2 instance has an API and no way to deliver the browser application. Until it does, every V2 screen can be tested only against mocks and no user can open V2. Serve the built bundle from the V2 application under the same origin, as the SQLite application already does.

## Context

### Current behaviour

- `src/wealth_ledger/web_v2/api.py:26-38` enumerates every allowed path and method (`ROUTES`, `DYNAMIC`, `SOURCE_ROUTES`, `ANONYMOUS`); requests outside it are refused. No path serves HTML or assets.
- The SQLite application serves `index.html` for `/`, `/login`, `/app` and `/app/{page:path}` and the hashed assets (`src/wealth_ledger/web/frontend.py:33-36`), with its security headers set in `src/wealth_ledger/web/api.py`.
- The Docker context helper already ships the built frontend (`scripts/docker_context.py`).

### Expected behaviour

- A V2 instance serves `index.html` for `/`, `/login`, `/setup`, `/register`, `/app` and paths under `/app/`, and static assets under `/assets/`, without authentication.
- API behaviour, CSRF, origin and host checks are unchanged. Unknown non-asset paths outside `/app/` still get the existing refusal.
- Responses carry the same content-security and cache headers as the SQLite application.
- When no bundle is present, the API still starts and the HTML routes answer with a clear 404.

### Scope

- In scope: static and HTML routes in the V2 app, the allowlist entries, headers, tests, one paragraph in the V2 operator guide.
- Out of scope: any page (WL-P0-011A to F), a reverse-proxy recipe, changes to the v1 serving code.

### Implementation notes

- Reuse the serving helper in `src/wealth_ledger/web/frontend.py` instead of copying it; if it cannot be shared as is, extract the common part without changing v1 behaviour.
- Add the new paths to the anonymous allowlist only for GET, and only for the HTML and asset paths.
- Path traversal: serve assets only from the bundle directory by exact file name; v1 tests show the cases to copy (`tests/test_web.py`).

## Acceptance criteria

- [ ] Given a V2 instance with a bundle, when a browser requests `/`, `/login` or `/app/investments`, then `index.html` is returned with the same security and cache headers the SQLite application sends for `/`.
- [ ] Given a hashed asset path, then the file is returned with the same headers as in the SQLite application; given `/assets/../x` or an unknown asset, then 404.
- [ ] Given `POST /` or any non-GET on these paths, then the existing refusal applies.
- [ ] Given no bundle directory, then the API routes work and HTML routes return 404 with a JSON error.
- [ ] Every existing test in `tests/test_web_v2_api.py` and `tests/test_web.py` passes unchanged.

### Tests

- New cases in `tests/test_web_v2_api.py` for each criterion.
- One browser smoke test that loads the V2 shell from a V2 app once WL-P0-011A exists.
