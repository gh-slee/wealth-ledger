# WL-P2-007: Offer a one-command synthetic demo instance for evaluators

## Goal

Someone evaluating the project has to build an image, initialize an owner on the host, create a portfolio and import their own files before they see a single screen. The repository already contains a disposable synthetic server used by the browser tests. Expose it as a documented demo command so a visitor can look at every page with invented data in one step, and decide whether to install.

## Context

- `scripts/web_browser_fixture.py` builds a temporary instance with four synthetic portfolios, starts a worker and serves on `KURAFOLIO_E2E_PORT`. It prints nothing about the sign-in it creates and is documented only for tests.
- `scripts/web.py` subcommands are `init-owner`, `reset-password`, `upgrade`, `backup`, `restore`, `maintenance-clear`, `adopt-preview`, `adopt-confirm`, `worker` and `serve`. There is no demo.
- README "try an offline report demo" (`examples/demo.py`) produces files only, not the Web UI.
- Scope: a `demo` entry point that reuses the fixture builder, binds to `127.0.0.1` only, prints the URL and the synthetic sign-in, shows a persistent "synthetic demonstration data" banner in the UI, and deletes its temporary directory on exit. README and docs/getting-started.md gain a short "Look around first" section.
- Out of scope: shipping demo data into real instances, a hosted public demo, any change to `init-owner`, changes to the browser-test behaviour of the fixture.
- The demo must refuse to start when `KURAFOLIO_DATA_ROOT` points at an existing instance.

## Acceptance criteria

- [ ] From a checkout with the Web dependencies installed and a built frontend, one documented command starts the demo and prints the local URL and sign-in.
- [ ] Every page shows a banner stating the data is invented; the banner is absent from instances created with `init-owner`.
- [ ] The demo never reads or writes a path outside its temporary directory, and refuses to run against an existing data root.
- [ ] Stopping the command removes the temporary directory and the worker process.
- [ ] `npm --prefix frontend run test:e2e` still passes unchanged; a Python test covers the refusal and the cleanup.
- [ ] README and getting-started describe the demo and state that it is not an installation.

## Plan

- [ ] Owner approves the entry point name and the banner.
- [ ] Extract the fixture builder into an importable function; keep the test script as a thin caller.
- [ ] Add the demo command, banner flag and tests.
- [ ] Update README, getting-started and screenshots if the banner appears in them.
