# WL-P2-006: Add a Python lint gate that applies to new and changed code

## Goal

The Python sources have no linter, formatter or type checker in CI. About 900 lines under `src/` are longer than 160 characters and 232 are longer than 300; several route modules join statements with semicolons. Reviewers and agents read diffs in which one changed line holds several statements. Add a lint gate that stops this from growing without reformatting existing files, which would conflict with every open ticket branch.

## Context

### Evidence (2026-11-09)

- `pyproject.toml`, `requirements*.lock` and `.github/workflows/ci.yml` name no ruff, flake8, mypy, pyright or black.
- `awk 'length>160' $(find src -name '*.py') | wc -l` gives 900. `src/wealth_ledger/persistence/ingestion_schema.py` has a 2,601-character line (SQL text) and 425 `; `-joined lines.
- The frontend already has Prettier, `tsc --noEmit` and a source check.

### Scope

- In scope: a pinned linter in the development lock files only; a configuration that enables a small rule set (unused imports and names, undefined names, multiple statements on one line, a line-length ceiling); a per-file baseline so existing violations are recorded and do not fail; one CI step; a paragraph in `docs/development.md`.
- Out of scope: reformatting existing files, type checking, any change under `src/` beyond what the baseline tool writes to its own file, runtime dependencies.
- Non-goals: a formatter. Mass formatting needs its own decision when few branches are open.

### Implementation notes

- SQL text blocks in `ingestion_schema.py`, `identity_schema.py` and `source_schema.py` are rendered contract text. Exclude them from line-length rules by path.
- The lock files are hash-pinned; follow [development.md](../docs/development.md) for regenerating them. The tool must not enter `requirements.lock` or the Docker runtime image.

## Acceptance criteria

- [ ] CI fails when a pull request adds a new violation of the enabled rules in a file under `src/`, `scripts/` or `tests/`.
- [ ] CI passes on the current tree without any source file being reformatted.
- [ ] The baseline file is generated by a documented command and can only shrink: a test or CI step fails if a count rises.
- [ ] `python scripts/dependency_inventory.py --require-declared` still passes and the runtime image contents are unchanged.
- [ ] `docs/development.md` explains how to run the check locally.

## Plan

- [ ] Owner approves the tool and rule set.
- [ ] Add the pinned tool and configuration.
- [ ] Generate the baseline; add the CI step.
- [ ] Document.

## Decisions needed

1. Tool. Options: ruff (one binary, fast, baseline through per-file ignores) or flake8 with plugins. Recommendation: ruff.
2. Line-length ceiling for new code. Options: 100, 120 or 160. Recommendation: 120.
