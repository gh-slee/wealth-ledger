# WL-P2-008: Plan the retirement of superseded import paths after the V2 cutover

## Goal

The version 1 API exposes four families of import endpoints that grew one after another, and V2 adds a fifth. Each needs tests, documentation and compatibility guards, and each is a place where a future change can break history. No ticket says which of them stop accepting new work after the cutover and which stay as read-only compatibility. Produce that plan so WL-P0-015 can state the supported surface truthfully and later tickets can remove code safely.

## Context

- Version 1 routes today (from `src/wealth_ledger/web/`): `/previews` and `/jobs` (`imports.py`), `/source-plans` and `/source-context-plans` (`source_plans.py`), `/source-import-previews`, `/source-report-previews` and `/source-reports` (`source_reports.py`), `/source-ingestion-previews` and `/source-ingestions` (`source_submissions.py`), plus `/financial/previews` and `/financial/jobs` (`financial.py`).
- The CLI has matching entry points (`cli.py`, `source_cli.py`, `source_import_cli.py`, `source_submission_cli.py`, `source_report_cli.py`, `wallet_cli.py`).
- The package root holds 22 `source_*.py` modules in one flat namespace.
- AGENTS.md requires explicit native compatibility and frozen legacy history to keep working. This ticket proposes nothing that drops stored data or saved editions.
- Scope: an inventory of every import and publication entry point with its callers, tests and documents; a proposed status for each after cutover (kept, read-only, removed in a named later release); the order in which removal tickets could run. Out of scope: removing or changing any code.

## Acceptance criteria

- [ ] A document under `docs/` lists each entry point, its module, its tests and its proposed post-cutover status.
- [ ] For each path proposed for removal, the document names the evidence that no saved data, edition or recovery flow depends on it, or marks it as kept.
- [ ] The owner has approved or amended the list; the decision is recorded in the Log.
- [ ] Follow-up tickets exist for each approved removal, each with its own compatibility test.

## Plan

- [ ] Inventory routes, CLI commands and their tests.
- [ ] Draft statuses and the removal order.
- [ ] Owner review; file follow-ups.
