# WL-P0-011A: Build the eight-route shell and navigation

## Goal

Build the V2 application shell: the eight approved destinations with Exposures nested under Stock/Bond, the routes, navigation for desktop and phone, and shared empty, loading, error and not-found states, in en-CA, zh-TW and zh-CN, against mocked APIs. The shipped nine-page application stays the default UI until cutover (WL-P0-014) and must keep working unchanged.

## Context

### Current behaviour

- The shipped shell is `frontend/src/App.tsx`: nine destinations (`:58-68`), a portfolio selector and "New portfolio" (`:376-418`), an edition selector (`:455-482`), routes under `/app/:portfolio/:page?` (`:267-273`).
- Observed on the synthetic fixture on 2026-11-10 at 375x812: navigation and settings fill the first 380 px; three of nine destinations fit in a sideways-scrolling row; an unknown page silently renders Overview; interface language is lost on reload.
- The V2 backend serves no frontend: `src/wealth_ledger/web_v2/api.py:26-37` lists API routes only, while v1 serves the bundle from `src/wealth_ledger/web/frontend.py:33-36`.
- No V2 page exists. The shipped UI talks only to `/api/v1` (`frontend/src/lib/api.ts`).

### Expected behaviour

- Destinations and routes: Home `/app`, Stock/Bond `/app/investments` with child Exposures `/app/investments/exposures`, Crypto `/app/crypto`, Total `/app/total`, Import Data `/app/import`, Parser Plugin Store `/app/sources`, App Settings `/app/settings`, Profile `/app/profile`. Sign-in and registration are outside the eight.
- Stock/Bond and Crypto appear when a matching source is enabled or data exists; otherwise the page offers "Enable a source".
- Each destination renders a titled placeholder with loading, empty and error states until its own ticket fills it.
- No portfolio selector, no "New portfolio", no edition selector, no "Financial records" destination.
- Phone: one compact bar with a menu button; content starts on the first screen.
- An unknown path under `/app` shows "Page not found" with a link to Home.

### Scope

- In scope: the V2 shell, routing, navigation, shared states, locale keys, browser tests.
- Out of scope: page content (WL-P0-011B to F, WL-P0-012B to E, WL-P0-013B), any change to the shipped nine-page routes, removing shipped pages.
- Non-goals: a new visual identity. Keep the existing tokens and components.

### Implementation notes

- Reuse `frontend/src/components/data-table.tsx`, `chart.tsx`, `ui/button.tsx`, `lib/format.ts`, `lib/i18n.tsx`, `lib/theme.tsx` and the tokens in `frontend/src/styles.css`. Read [DESIGN.md](../DESIGN.md), [PRODUCT.md](../PRODUCT.md) and [web-frontend.md](../docs/web-frontend.md).
- Browser tests intercept `/api/v2` with Playwright `page.route`, as `frontend/tests/browser/onboarding.spec.ts` does for `/api/v1`.
- Add locale keys in a block named for this ticket to reduce merge conflicts; rebase before the PR.
- Select the shell from what the backend reports, not from a build flag: a V2 instance answers `GET /api/v2/auth/csrf`, a SQLite instance answers `GET /api/v1/auth/csrf`. See Decisions needed.
- Carry over UX-P1-009 (selections in the URL) and UX-P1-010 (remembered language) if merged; otherwise implement the same behaviour here.
- Use `@radix-ui/react-dialog` for the phone menu (`frontend/src/components/imports.tsx:996-1030` shows the pattern).
- The longer draft spec is in the local planning package until WL-P0-016 publishes it. This ticket is written to be sufficient without it.

## Acceptance criteria

- [ ] Given a V2 instance, then exactly eight primary destinations and the Exposures child are present and each route renders its titled placeholder.
- [ ] Given a SQLite instance, then the shipped nine-page UI renders unchanged and the existing browser suite passes without edits.
- [ ] Given 375x812, when any V2 destination loads, then `<main>` starts within the first 120 px and the menu lists all destinations with targets at least 42 px high and no horizontal scrolling.
- [ ] Given the phone menu is open, then focus is trapped, Escape closes it and focus returns to the menu button; choosing a destination moves focus to the page heading.
- [ ] Given an unknown path under `/app`, then "Page not found" is shown with a working link to Home.
- [ ] Given no securities source and no securities data, then Stock/Bond offers "Enable a source"; given data from a disabled source, the destination stays reachable.
- [ ] The V2 shell contains no portfolio selector, "New portfolio", edition selector or "Financial records" entry, and Home contains none of the seven banned concepts listed in WL-P0-012D.
- [ ] Interface language survives a reload.
- [ ] Keyboard reachable with visible focus, one `h1` per page, labelled controls, no colour-only meaning; en-CA, zh-TW, zh-CN; light and dark; 375 px and 1024 px.
- [ ] README screenshots are added for the V2 shell with synthetic data.
