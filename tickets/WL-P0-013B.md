# WL-P0-013B: Add the V2 download panel

## Goal

A V2 user viewing any analysis page wants to download what they are looking at. Give every analysis page one Download control that requests an export of the displayed calculation, shows progress and delivers the file, while the user keeps browsing.

## Context

### Current behaviour

- No V2 page exists. The shipped UI talks only to `/api/v1` (`frontend/src/lib/api.ts`).
- Shipped equivalent: the report reader lists files of a saved edition by file name (`frontend/src/components/report-reader.tsx:246-310`) and `report-exports.tsx` offers data exports. Observed 2026-11-10: links read "portfolio.ods", "report.md", "report.pdf".
- Routes come from WL-P0-013A; the toolbar entry point from WL-P0-012B.

### Expected behaviour

- Download opens a panel listing formats by name ("PDF report", "Spreadsheet (ODS)", "Markdown") and stating the valuation time, currency and language being exported.
- Choosing a format starts a job, shows progress, and offers the file when ready. The panel can be closed and reopened; a finished export stays listed for the session.
- Failure shows the reason and a retry that reuses the same request identity.

### Scope

- In scope: the panel, its states, locale keys, tests.
- Out of scope: rendering (WL-P0-013A), scheduling exports, sharing links.

### Implementation notes

- Reuse `frontend/src/components/data-table.tsx`, `chart.tsx`, `ui/button.tsx`, `lib/format.ts`, `lib/i18n.tsx`, `lib/theme.tsx` and the tokens in `frontend/src/styles.css`. Read [DESIGN.md](../DESIGN.md), [PRODUCT.md](../PRODUCT.md) and [web-frontend.md](../docs/web-frontend.md).
- Browser tests intercept `/api/v2` with Playwright `page.route`, as `frontend/tests/browser/onboarding.spec.ts` does for `/api/v1`, until a synthetic V2 fixture exists.
- Add locale keys to all three catalogs in one block named for this ticket; rebase before the PR.
- Use `@radix-ui/react-dialog` as `frontend/src/components/imports.tsx:996-1030` does.
- Downloads go through an authenticated fetch like `downloadFile` in `frontend/src/lib/api.ts`; never a public URL.
- The export pins the calculation identifier the page is showing, not "latest".

## Acceptance criteria

- [ ] Given a displayed calculation, when the user requests a PDF, then the request carries that calculation identifier, currency and locale.
- [ ] Given a running export, then progress is announced once (`role="status"`) and background polling does not move focus.
- [ ] Given the page data refreshes while an export runs, then the delivered file still matches the pinned calculation named in the panel.
- [ ] Given a failure, then the reason and a retry are shown; retry does not create a duplicate job.
- [ ] Given the panel is open, then focus is trapped, Escape closes it and focus returns to the Download button.
- [ ] Keyboard reachable with visible focus, one `h1`, labelled controls, chart data available as a table, no colour-only meaning; en-CA, zh-TW, zh-CN; light and dark; 375 px and 1024 px.
