# WL-P0-007M: Decide how a re-upload gets back a raw slot that finish could not prove

## Goal

When `finish_member_v1` ends an attempt with `reupload_required` but its launcher proofs are missing, `pending` or `failed`, the attempt keeps its raw slot. Each user has one raw slot, so the next `reserve` for that set returns `import_busy`. WL-P0-007C releases such a slot only after the set becomes terminal (cancel, rejection, commit or expiry), which can take up to 24 hours. The owner decides whether a live set should also be able to prove and release that slot, and by which call.

## Acceptance criteria

- [ ] The owner records a decision on whether and how a held slot of a fenced attempt in a live set is released.
- [ ] If a change is chosen, a follow-up implementation ticket names the function, its fencing and its PostgreSQL tests.

## Plan

- [ ] Write the options (for example: a normalize-scoped cleanup call on the finished attempt; a reserve that accepts proofs for the previous fence; keep the current terminal-only release) with a recommendation.
- [ ] Ask the owner and record the answer.

## Decisions needed
