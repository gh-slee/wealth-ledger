# WL-P0-009A: Add the quote adapter contract and an optional unofficial market-data adapter

## Goal

The owner wants live prices for any stock, ETF or bond a user holds in the first V2 release, and decided on 2026-11-10 to include an adapter for unofficial market-data endpoints, because no verified free official source covers Toronto-listed securities yet. Define the quote adapter contract every provider implements, a fake provider for tests, and that optional adapter.

## Context

### Current behaviour

- Prices today: Bitcoin from the Coinbase Exchange public API (`src/kurafolio/prices.py:88`) and USD/CAD from the Bank of Canada Valet API (`src/kurafolio/fx.py:12`). There is no stock or ETF quote source; the shipped application uses the market values inside the imported file.
- WL-P0-009 owns refresh scheduling, the currency registry and the choice of an official keyed provider, and is blocked on that choice.
- A web search on 2026-11-10 found free official tiers small, personal-use only and unconfirmed for Toronto listings ([PRODUCT_CONTEXT.md](PRODUCT_CONTEXT.md)).

### Expected behaviour

- One adapter interface: latest quote and daily history for a listing identified by exchange and symbol, each result carrying price, currency, "as of" time, source name and a delay class (real time, delayed, end of day).
- A deterministic fake provider used by all tests; tests never call the network.
- An unofficial-endpoint adapter that the instance operator enables explicitly in configuration. It is off by default, and the operator guide states that such endpoints can change or disappear and that their terms of use are the operator's responsibility.
- When a provider fails or has no data for a listing, the previous valid price is kept and marked stale with its time; nothing becomes zero.
- Requests are batched, cached and rate limited per instance so several users holding the same listing cause one upstream request.

### Scope

- In scope: the interface, the fake, the unofficial adapter, per-instance cache and rate limit, configuration, tests, operator documentation.
- Out of scope: the scheduler and manual-refresh route, the currency registry and an official keyed provider (all WL-P0-009); any page (WL-P0-012B).

### Implementation notes

- Model the evidence fields on the existing quote record in `src/kurafolio/prices.py:88-100` (provider, pair, as-of).
- Listing identity must use exchange plus symbol; the Wealthsimple file provides `Symbol`, `Exchange` and `MIC` columns (`examples/data/wealthsimple-holdings.csv`). A bare ticker is ambiguous across exchanges.
- Use `Decimal` for prices; never float arithmetic (AGENTS.md).
- No provider credentials in the repository; any key is an operator secret file.
- Record raw responses needed for audit only as bounded, non-personal evidence, as the existing adapters do.

## Acceptance criteria

- [x] Given the fake provider, then latest quote and daily history for a Toronto-listed and a US-listed symbol return the fixed oracle values with currency and "as of" time.
- [x] Given the unofficial adapter is not enabled in configuration, then no request leaves the instance and quotes report "no provider".
- [x] Given it is enabled, when a listing is requested by two users within the cache window, then one upstream request is made.
- [x] Given the upstream returns an error, an unexpected shape or no data, then the last valid price is returned marked stale and the failure is logged without secrets.
- [x] Given an unknown listing, then the result is "unavailable" with a reason, never zero.
- [x] The operator guide explains how to enable the adapter and states its limits and the operator's responsibility for terms of use.

### Tests

- Unit tests with recorded synthetic responses for success, error, malformed and empty cases.
- A test that fails if any test opens a network connection.

## Decisions needed

1. Which unofficial endpoint. The owner decided on 2026-11-10 that the implementing agent first runs a short spike on Toronto-listed and US-listed ETFs, reports the candidate endpoint with coverage, delay and observed limits, and waits for the owner to approve the named endpoint before writing it into code. The adapter interface, fake provider, cache and rate limit do not wait for this.

   Spike run on 2026-11-12 around 18:55 UTC (a Thursday, during trading hours), public symbols only:

   | Candidate | Toronto (VEQT.TO, XIU.TO, XBB.TO, ZAG.TO) | US (SPY, VTI) | Observed |
   |---|---|---|---|
   | Yahoo Finance chart endpoint, `query1`/`query2.finance.yahoo.com/v8/finance/chart/<symbol>` | Covered, CAD, exchange `TOR`, `.TO` suffix | Covered, USD, exchange `PCX` (NYSE Arca) | Latest price was 1 to 5 minutes old; the response has no delay field, so the adapter would report `delayed`. Daily closes for a date range are in the same response. One symbol per request; the batch quote endpoint (`v7/finance/quote`) answers 401 without a session cookie. 30 requests in a row with the client name `Kurafolio/1.0` all returned 200. Generic library client names (`curl`, `python-urllib`) get 429, so the adapter must send its own honest client name; it would not imitate a browser. Unknown symbol: 404 with a JSON error "No data found". Prices are JSON floats with binary noise in history closes (62.15999984741211), so the adapter must parse them as Decimal and round to the listing's tick (2 decimals for these listings) |
   | Stooq CSV, `stooq.com/q/l/` | 404 | 404 | The endpoint no longer answers; not viable |

   Answered by the owner on 2026-11-12: approved the Yahoo Finance v8 chart endpoint as recommended.

   Recommendation: approve the Yahoo Finance v8 chart endpoint as the unofficial adapter, registered as `unofficial-yahoo-chart`, one request per listing, `delay_class: delayed`, history from the same endpoint, client name `Kurafolio/<version>`, MIC mapped to Yahoo suffixes for XTSE (`.TO`), XTSX (`.V`) and US MICs (no suffix). Its terms of use are the operator's responsibility, as the operator guide states. Bond coverage was not tested; Wealthsimple bond positions without a listing stay unavailable.
